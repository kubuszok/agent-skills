# Generated-code performance with Hearth

Techniques (measured in Kindlings' codecs) for making macro output fast, small and warning-free. Profile before optimizing; keep a slow but simple fallback path when an optimization needs compile-time knowledge.

**Version.** Written for Hearth 0.4.5. Check the version in the user's build (build.sbt / build.mill / project.scala `//> using dep`); if it differs, prefer the docs for that version: https://scala-hearth.readthedocs.io/en/0.4.5/ (replace `0.4.5`).

## 1. Factory + lambdas instead of `new TC[A] { ... }`

Every expansion of an anonymous class creates a new `.class` file to load and verify. A factory in your **runtime** code is one class; per-type lambdas compile to `invokedynamic`. Kindlings measured equal steady-state throughput and 2.5-3x faster instance creation.

```scala
// runtime (public, binary-compatible - check with MiMa)
object ShowFactories {
  def instance[A](f: A => String): Show[A] = new Show[A] { def show(a: A): String = f(a) }
}
// macro
Expr.quote { ShowFactories.instance[A]((a: A) => Expr.splice(body(Expr.quote(a)))) }
```

Polymorphic type classes (`Functor[F]`): factories over sealed witness types (`(F[W1], W1 => W2) => F[W2]`, cast inside the factory) - see `hearth-hkt-derivation` for the rules (`W1` only as a type argument, `Any` for raw values, `type AnyF[X] = Any`).

## 2. Cached definitions at instance scope

`cacheState.toValDefs.use(_ => wholeInstanceExpr)` emits cached `lazy val`s (summoned instances, schemas, regexes) and `def`s once around the instance. Wrapping only a method body makes them locals re-initialized on **every call** (Kindlings saw a 6x slowdown). Cache structural types as `def`s - small methods JIT better and avoid the 64KB method limit (`Method too large`). See `hearth-def-caching`.

## 3. Evaluate configuration at compile time

```scala
configExpr.semiEval match {               // Either[NonEmptyVector[String], Config]
  case Right(cfg) => // precompute: field names, booleans -> skip dead branches entirely
  case Left(_)    => // fall back to runtime calls like config.fieldNameMapper(name)
}
```

`semiEval` handles literals, operators, objects/companion members on the classpath, constructor and method calls, lambdas without control flow, named/default args (and on Scala 3 local immutable vals, e.g. `inline` method arguments). It refuses: definitions (`def`/`var`/`lazy val`/classes) inside the tree, `match` anywhere, lambdas whose body uses `match`/`if`/loops/`try`/`return`/assignments, lambdas of arity > 22 on Scala 2, `var`s, local vals on Scala 2, and **members of the module being compiled** - so a config object defined next to the call site (typical in tests) always takes the runtime fallback; test that path too. Details and overrides: `hearth-expr-toolkit`.

## 4. Avoid boxing and indirection

- Accumulate decoded fields in typed locals: `ValDefs.createVar[Field](zero, "_name")` gives `(getter, setter)`; compose with `map2`/`traverse`, close with `.use { ... }` - no `Array[Any]`, no boxing of primitives.
- Field loop without duplicating the dispatch: `var l = -1; while (l < 0 || reader.hasMore) { l = readKey(); /* dispatch once */ }` - duplicated dispatch chains double method size and defeat JIT inlining.
- Built-in types: emit the direct call (`writer.writeVal(x.age)`) instead of calling a cached def or a summoned instance - but only when no user-provided implicit exists for that type (check with `summonExprIgnoring` first).
- Collections: emit a `while` loop calling cached defs directly, or use `isColl.foreach(expr)(item => ...)` (zero-closure by default, array providers iterate by index) instead of runtime helpers taking a `Function1` per element; pre-size builders with `isColl.sizeHintForBuilder(expr)` (`Option[Expr[Int]]`, `None` for single-pass sources; guard the runtime value with `>= 0`). Keep `LambdaBuilder` + helpers as a fallback.
- Positional access when the format allows it (`record.put(0, v)` instead of by name); write keys known at compile time as constants.

## 5. Keep generated methods small and linear

HotSpot never JIT-compiles a method over **8000 bytes** of bytecode; the hard limit is 64 KB ("Method too large"). Wide case classes cross both when the generated code grows faster than linearly with the number of fields. Rules:

- No `try`/`if`/`match` inside an argument list (constructor, `::`, builder call): the compiler spills every earlier argument, so the size is quadratic. Bind results with statements.
- Each field in its own local `def` (`ValDefs.createDef`, `FreshName.FromPrefix`), one flat statement per field. Fail-fast: `val rK = if (rK-1 ok) fieldK else rK-1`. Accumulating: `val eK = merge(eK-1, rK)`, with `null` = no failure yet.
- No nesting per field (`flatMap` chains, folds wrapping each step).
- Fail-fast and accumulating are two methods, not a runtime flag per field.
- Branch in the macro on whatever it knows (evaluated config, annotations, type shape); emit a runtime `if` only on the non-evaluable config path.
- Cast values to field types; never re-evaluate a decoder as a "type witness".
- No local `lazy val` in per-call code (a `LazyRef` and a lock per call). Build schemas, regexes and name or key tables once per instance, or in the macro.
- Splice each body once; refer to it by name.

[wide-types.md](wide-types.md) has a worked example: how a decoder failed at 88 fields, how to detect it (with a size-guard test), the fix in Hearth code, and the same mistake in other shapes.

## 6. Warning-free output

Users compile with `-Xfatal-warnings` and linters; they must not need `@nowarn` for code they did not write.

```scala
result.annotated[scala.annotation.nowarn]()                                           // { @nowarn val x = result; x }
result.annotated[java.lang.SuppressWarnings](Expr.quote(scala.Array("org.wartremover.warts.All")).asUntyped)
```

`annotated` needs implicit `Type`s for the annotation and the result (e.g. `implicit def nowarnType: Type[scala.annotation.nowarn] = Type.of[scala.annotation.nowarn]`).

Also: `expr.suppressUnused` (or `val _ = param`) for lambda parameters a body may not use, avoid hand-written `isInstanceOf` on Scala 3 enum singletons - use `Enum[A].matchOn` / `MatchCase.eqValue`, which emit `case x @ EnumValue` (`hearth-case-classes-and-enums`), test the generated code under `-Xfatal-warnings` with many linters on both Scala versions.

## 7. Separate runtime helpers from generated code

Put everything generated code calls (factories, helpers for types that cannot be quoted) in a small public runtime package and check it with MiMa: generated code from older library versions keeps linking, while macro internals stay free to change. Do not call Hearth (`hearth.fp`, `MIO`) from generated code - it is compile-time only and may not link on Scala.js/Native.

## Verification

- Bytecode: `javap -c -p` the generated classes; look for `BoxesRunTime`, `Function1.apply` in hot paths, per-type `$anon` classes, `LazyRef` in methods that run per call.
- **A size guard test:** a 100-field fixture, failing when any generated method exceeds 8000 B, on Scala 2.13 and 3, with a compile-time and a runtime config ([wide-types.md](wide-types.md)).
- JMH benchmarks against the upstream library (with JFR/async-profiler to find the hot spot), including a **wide type** and the **runtime-config path**; `-prof gc` for allocations.
- Behaviour unchanged: round-trip and golden tests on both Scala versions.
